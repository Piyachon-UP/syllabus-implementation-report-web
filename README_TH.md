# Smart Syllabus Implementation Report Web v0.2.0

ระบบรายงานผลการดำเนินงานตาม Syllabus — คณะวิทยาศาสตร์ มหาวิทยาลัยพะเยา

**รุ่น v0.2.0 เพิ่มการสร้างเอกสาร Word (.docx) ใน Browser** ต่อยอดจากรุ่น v0.1.0 โดยไม่เปลี่ยน JSON Schema, สถานะการรายงาน, หรือวิธีบันทึก JSON เดิม

## วิธีใช้งาน

1. เปิดเว็บไซต์ GitHub Pages ของ Repository `syllabus-implementation-report-web` (หรือเปิด `index.html` บนคอมพิวเตอร์)
2. เลือก **นำเข้า Syllabus** แล้วเปิดไฟล์ `.json` ที่จัดทำไว้ใน Smart Syllabus Generator หรือกด **เปิดรายงานเดิม** แล้วเลือกไฟล์ `SYLLABUS_REPORT_....json` เพื่อทำต่อ
3. ตรวจข้อมูล **รายวิชา** และ **ผู้สอน** (แสดงแบบอ่านอย่างเดียว ไม่แก้ต้นฉบับ)
4. ไปที่ **ผลการจัดการเรียนการสอน** เลือก Lecture/Lab และระบุ `ตามแผน` / `ไม่ตามแผน` ทุกสัปดาห์ หากไม่ตามแผนต้องระบุสาเหตุและการดำเนินการ
5. ไปที่ **ผลการประเมิน** ระบุ `บรรลุ` / `ไม่บรรลุ` ในแต่ละรายการ หากไม่บรรลุต้องระบุสาเหตุและการดำเนินการ
6. กด **บันทึกรายงาน JSON** เพื่อดาวน์โหลดข้อมูลที่แก้ไขไว้ และใช้ JSON นี้เปิดทำงานต่อภายหลัง
7. กด **สร้าง DOCX** เพื่อดาวน์โหลดรายงาน Word จากข้อมูลที่แสดงในขณะนั้น (รวมผลที่ยังไม่ระบุ)

> **สำคัญ:** กด **สร้าง DOCX** ไม่ใช่การบันทึกรายงาน JSON การสร้าง Word ไม่เปลี่ยนสถานะบันทึก ผู้ใช้ควรกด **บันทึกรายงาน JSON** เพื่อเก็บไฟล์ที่ใช้แก้ไขต่อก่อนปิด Browser

## รูปแบบเอกสาร DOCX

- หน้า A4 **แนวนอน** เพื่อรองรับตารางหลายคอลัมน์
- ชื่อรายวิชา ปีการศึกษา ภาคเรียน กลุ่มเรียน วันที่จัดทำรายงาน และสรุปจำนวนผลการดำเนินงาน
- ข้อมูลรายวิชา/หลักสูตรและข้อมูลผู้สอนจาก Syllabus JSON
- ตารางผลการสอน Lecture และ Lab: **สัปดาห์ · หัวข้อ/กิจกรรม · วิธีสอน · CLO · ผู้สอน · ผลการสอน · สาเหตุ · การดำเนินการ**
- ตารางการประเมิน: **รายการประเมิน · ประเภท · น้ำหนัก · CLO · ผลการประเมิน · สาเหตุ · การดำเนินการ**
- รายการที่ยังไม่ระบุสถานะจะมีข้อความ **ยังไม่ระบุ** และหากสาเหตุ/การดำเนินการยังไม่ครบจะคงช่องว่าง (—) ตามข้อมูลต้นทาง
- รายงานยังสร้างได้แม้ยังไม่ได้กรอกผลครบ จึงควรตรวจและแก้ไขรายการที่ยังไม่สมบูรณ์ก่อนใช้เป็นเอกสารราชการ

ไฟล์ Word ใช้ชื่อ `SYLLABUS_REPORT_<รหัสวิชา>_<ปีการศึกษา>_<ภาคเรียน>_<กลุ่มเรียน>.docx` สอดคล้องกับไฟล์ JSON

## โครงสร้างและการ Deploy

- `index.html` — เว็บไซต์ไฟล์เดียว (Self-contained) สำหรับ GitHub Pages
- `src/app.js` — ฟอร์มและบันทึกรายงาน JSON
- `src/report_docx.js` — ตัวสร้าง Word โดยใช้ OOXML + ZIP ใน JavaScript
- `src/styles.css` — Responsive Layout
- `src/index.template.html`, `tools/build.py` — สร้าง `index.html`
- `tools/test_web.py`, `tools/test_docx.py` — ทดสอบ JSON/Responsive/DOCX
- `schema/syllabus_implementation_report.v1.schema.json` — JSON Schema **คงเดิม**
- `sample/demo_syllabus.json`, `sample/demo_report.json` — ข้อมูลสมมติสำหรับทดสอบ (ไม่ใช่รายวิชาจริง)

หากแก้ Source Code ให้รันจากโฟลเดอร์โปรเจกต์:

```powershell
py -3 tools/build.py
```

จากนั้นอัปโหลดไฟล์ที่เปลี่ยนไปยัง Branch `develop` และดาวน์โหลด ZIP จาก Branch นี้มาทดสอบ `localhost:8000` ก่อนทำ Pull Request ไปยัง `main`

**ไม่ต้องเชื่อมต่อ Backend, CDN, Node.js หรือ Python ระหว่างใช้งานจริงบน GitHub Pages** (Python ใช้ Build ฝั่งนักพัฒนาเท่านั้น)

## ความเป็นส่วนตัวและความเข้ากันได้

- Syllabus JSON ต้นฉบับและ Report JSON ไม่ถูกส่งขึ้น Server ในระหว่างใช้งานปกติ
- การ Export DOCX ไม่แก้ JSON ต้นฉบับหรือ JSON รายงาน
- รองรับ Report JSON จาก v0.1.0 และ Syllabus JSON SchemaVersion 1.x ตามเดิม
- ไม่ควร Commit JSON รายงานจริงหรือไฟล์ Word ที่มีข้อมูลบุคคลลงใน Repository แบบ Public
