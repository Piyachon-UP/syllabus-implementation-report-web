# Smart Syllabus Implementation Report Web (Pilot v0.1.0)

ระบบเว็บสำหรับรายงานผลการดำเนินงานตาม Syllabus ของคณะวิทยาศาสตร์ มหาวิทยาลัยพะเยา

ระบบนี้เป็น **เว็บไซต์ใหม่แยกจาก Smart Syllabus Generator** เพื่อไม่ให้มีผลต่อเว็บไซต์ที่อาจารย์กำลังใช้งานอยู่

## คุณสมบัติ

- ทำงานใน Browser โดยใช้ HTML, CSS และ JavaScript เท่านั้น ไม่ต้องติดตั้ง Python หรือสร้าง Backend
- **นำเข้า Syllabus JSON** ที่ได้จาก Smart Syllabus Generator (ทดสอบกับไฟล์รูปแบบ `SchemaVersion: "1.0.0"`)
- ข้อมูล **CourseInfo / Curriculum / Instructors** แสดงแบบอ่านอย่างเดียว โดยแสดงข้อมูลทุกฟิลด์ที่มีอยู่ในไฟล์
- ดึงรายการ **LecturePlans / LabPlans** ทุกสัปดาห์ (รวมแผนที่มีสัปดาห์ซ้ำกัน) และแสดงข้อมูลแผนเดิม
- ให้เลือกรายสัปดาห์ **ยังไม่ระบุ / ตามแผน / ไม่ตามแผน** ถ้าเลือก **ไม่ตามแผน** ต้องกรอก **สาเหตุ** และ **การดำเนินการ**
- ดึง **Assessments** ทุกข้อและให้เลือก **ยังไม่ระบุ / บรรลุ / ไม่บรรลุ** ถ้าเลือก **ไม่บรรลุ** ต้องกรอก **สาเหตุ** และ **การดำเนินการ**
- มีสรุปจำนวนรายการทั้งหมด ระบุผลแล้ว ผลเป็นลบ และยังไม่ระบุผล
- บันทึกเป็น **รายงาน JSON ใหม่** ได้ แม้ยังไม่กรอกครบ และเปิดไฟล์รายงาน JSON กลับมาแก้ไขต่อได้
- ใช้งาน Responsive บน Desktop, Tablet และ Smartphone

## การใช้งานจริง

1. เปิด `index.html` หรือเว็บไซต์ GitHub Pages ของ Repository นี้
2. คลิก **นำเข้า Syllabus** และเลือกไฟล์ JSON ของรายวิชาที่สร้างจาก Smart Syllabus Generator
3. ตรวจข้อมูลรายวิชาและข้อมูลผู้สอนที่แสดงแบบอ่านอย่างเดียว และเลือก **วันที่จัดทำรายงาน** (หากต้องการ)
4. คลิก **ผลการจัดการเรียนการสอน** → เลือกแท็บ **บรรยาย** หรือ **ปฏิบัติการ** → เลือกผลการสอนในแต่ละสัปดาห์
5. ถ้าเลือก **ไม่ตามแผน** ให้กรอกทั้ง **สาเหตุ** และ **การดำเนินการ** เช่น การจัดสอนชดเชย
6. คลิก **ผลการประเมิน** → เลือก **บรรลุ** หรือ **ไม่บรรลุ** ของแต่ละรายการประเมิน
7. ถ้าเลือก **ไม่บรรลุ** ให้กรอกทั้ง **สาเหตุ** และ **การดำเนินการ**
8. กด **บันทึกรายงาน JSON** ที่แถบด้านล่าง ระบบจะดาวน์โหลดไฟล์ชื่อ `SYLLABUS_REPORT_....json` ไปยังเครื่อง
9. วันถัดไปคลิก **เปิดรายงานเดิม** เลือกไฟล์รายงาน JSON เพื่อกลับมาแก้ไขต่อ (ไม่ต้องนำเข้า Syllabus แยกอีก)

**สำคัญ:** การบันทึกเป็นการดาวน์โหลดไฟล์ JSON **ไม่ใช่ Auto Save และไม่ใช่การบันทึกบน Google Drive/GitHub** ควรตรวจสอบว่าดาวน์โหลดไฟล์สำเร็จก่อนปิดเว็บไซต์ และอัปโหลดไปยัง OneDrive/Google Drive ด้วยตนเองหากต้องการสำรองข้อมูล

## รูปแบบข้อมูล

- ไฟล์ Syllabus ต้นฉบับ **ไม่ถูกแก้ไข** และยังใช้ `SchemaVersion: "1.0.0"` ตามเดิม
- ไฟล์รายงานใช้ `ReportSchemaVersion: "1.0.0"` **ซึ่งเป็น Schema คนละชุด** กับไฟล์ Syllabus
- เก็บสำเนา JSON ต้นฉบับไว้ภายใน `SourceSyllabus` เพื่อเปิดไฟล์รายงานกลับมาได้โดยไม่ต้องนำเข้า Syllabus ซ้ำ
- `LectureResults` / `LabResults` และ `AssessmentResults` บันทึก `SourceIndex`, `Status`, `Reason`, `Action` โดยการจับคู่กับข้อมูลต้นฉบับใช้ `SourceIndex` เป็นดัชนีตำแหน่งรายการ (เริ่มที่ 0)
- **ผลที่ยังไม่ระบุเป็นค่า `""`** และไม่ถูกนับว่า "ตามแผน" หรือ "บรรลุ" โดยอัตโนมัติ
- รายการที่เป็นลบสามารถบันทึกแม้กรอกสาเหตุ/การดำเนินการไม่ครบ เพื่อให้ทำต่อภายหลังได้ แต่ UI แสดงรายการที่ยังขาดข้อมูล
- เมื่อเปลี่ยนผลที่เคยกรอกสาเหตุ/การดำเนินการ ระบบจะขอยืนยันก่อนล้างข้อความสองช่องเพื่อป้องกันข้อมูลค้างผิดสถานะ
- ไม่ควรแก้ลำดับรายการใน `SourceSyllabus` ภายในไฟล์รายงานด้วยมือ เพราะผลรายงานเชื่อมโยงกับรายการตามลำดับเดิม

รายละเอียด JSON Schema: `schema/syllabus_implementation_report.v1.schema.json`

## ไฟล์ตัวอย่าง (ใช้ข้อมูลสมมติ ไม่ใช่ข้อมูลอาจารย์จริง)

- `sample/demo_syllabus.json` — สำหรับทดลองนำเข้า Syllabus
- `sample/demo_report.json` — รายงานที่กรอกตัวอย่างบางส่วนแล้ว สำหรับทดลองเปิดรายงานเดิม
- `sample/UI_progress_desktop.png`, `sample/UI_assessment_mobile.png` — ภาพหน้าจอตัวอย่าง

## Deploy บน GitHub Pages (แนะนำให้สร้าง Repository ใหม่)

1. สร้าง Repository ใหม่ เช่น `syllabus-implementation-report-web`
2. อัปโหลด **เนื้อหาภายในโฟลเดอร์** นี้ (ไม่ต้องอัปโหลด ZIP) โดยให้ `index.html` อยู่ที่ Root
3. ไปที่ `Settings → Pages → Build and deployment` แล้วเลือก `Deploy from a branch`, `main`, `/(root)` และ `Save`
4. เปิด URL `https://YOUR-USERNAME.github.io/syllabus-implementation-report-web/`
5. ทดลองนำเข้าไฟล์ตัวอย่าง สถานะรายสัปดาห์ การบันทึกรายงาน JSON และการเปิดรายงานเดิม

ไม่ต้องสร้าง Repository ในชื่อเดียวกับ `syllabus-generator-web` เพราะเป็นคนละแอปและคนละ JSON Schema

**ความเป็นส่วนตัว:** โค้ดเว็บไซต์เผยแพร่แบบ Public ได้ แต่ไม่ควรอัปโหลดรายงาน JSON จริง ซึ่งอาจมีชื่อบุคลากรและรายละเอียดการดำเนินงาน ไปยัง Public Repository การนำเข้าและบันทึกทำใน Browser ของผู้ใช้ ไม่มีการอัปโหลดข้อมูลไปยัง Server ของเว็บ

## โครงสร้าง Source Code

```text
syllabus-progress-report-web/
├── index.html                  # เว็บไซต์ไฟล์เดียว พร้อม Deploy (Build แล้ว)
├── .nojekyll
├── src/
│   ├── index.template.html
│   ├── app.js
│   └── styles.css
├── tools/
│   ├── build.py                # รวม HTML/CSS/JS เป็น index.html
│   └── test_web.py             # ทดสอบอัตโนมัติ (ต้องติดตั้ง Playwright, jsonschema)
├── schema/
│   └── syllabus_implementation_report.v1.schema.json
└── sample/
    ├── demo_syllabus.json
    ├── demo_report.json
    └── ภาพประกอบ...
```

เมื่อแก้ `src/app.js` หรือ `src/styles.css` ให้รัน:

```powershell
py -3 tools/build.py
```

จากนั้น Commit **ทั้ง Source Code ที่แก้ และ index.html ที่ Build ใหม่**

## ขอบเขต Pilot v0.1.0

เวอร์ชันนี้รองรับ **Import Syllabus → บันทึกผลจริง → Save/Load Report JSON** เท่านั้น ยังไม่รวมการสร้าง DOCX รายงาน การสรุปทั้งคณะ การอนุมัติ และฐานข้อมูลส่วนกลาง ซึ่งสามารถพัฒนาต่อในรุ่นถัดไปโดยใช้รายงาน JSON ที่ได้เป็นข้อมูลต้นทาง
